### 二、先验一件没验过的事：我到底有没有 push 权限

> **`ls-remote` 只验了读。**

- **两个问题，第二个要命**：
  > **① `$env:TEMP` 返回的是 8.3 短名**（`C:\Users\S-WANG~1.WEL`）——`Set-Location` 直接失败；
  > **② `git push` 调起了 `sh.exe`，撞上沙箱的命名管道限制**——`couldn't create signal pipe, Win32 error 5`。
  > **但 `ls-remote` 之前是通的**（它不走 `sh`）。
- **重验，结论是硬的**：
  ```
  ls-remote   → exit 0   ✓ 读得到（公开仓库，不要凭据）
  push        → fatal: could not read Username for 'https://github.com'
                exit 128
  ```
  > **① 本机没有 GitHub 凭据**——`credential.helper = manager` 里没有它。
  > **② 那个 helper 在沙箱里还会崩**——它调 `sh.exe`，撞上命名管道限制。
  > **顺带发现第三个限制：`TEMP` 也不可写**（`Access to the path ... is denied`）——**所以暂存目录只能放在工作区内。**

### 五、卡在凭据上

- push 失败后，我去查凭据管理的实际状态。
- **而这里我要问的是一个具体的事实，不是方案**：
  > **你 `git push` 的时候，有没有弹窗？**
  - **弹了、你关掉了** → 重推，等它；
  - **弹了浏览器但你没登** → 登完就好；
  - **完全没弹** → 它是走了"终端输入"，那就是你手输用户名密码那一次。
- **两条路**：
  **A. 手动触发一次 GCM 认证**（会弹浏览器）：
  ```powershell
  'protocol=https
  host=github.com' | & 'C:\Program Files\Git\mingw64\bin\git-credential-manager.exe' get
  ```
  **它若输出 `username=` 和 `password=`，就说明凭据进去了**，再 push 就成了。
  **B. 用 PAT**（如果 A 不弹）：GitHub → Settings → Developer settings → **Fine-grained tokens** → **只给 `Artherine/vps` 的 `Contents: Read and write`**。拿到后**别写进 `.git/config`**，用 GCM 存。
