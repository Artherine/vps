### 五、10:02 他一句话把我那个"hash"揭了

- 他说：「:/ 你说的 session 被哈希钉死了嘛……不过这是好事，具体怎么实施?」
- **我认**：
  > **"hash"是我猜的，实际是"规范化 cwd"——差别很大**（hash 要算函数，规范化只要照抄规则 `\`→`-`、`:`→`-`、前后加 `--`）。
- **实施四步**：
  **① 备份**——把 `~\.dsh\sessions\--C-Artherine-DSH-Temp--\` 整个复制到工作区外。**这是唯一不可逆的一步。**
  **② 合并会话目录**——目标 `--C-Artherine-DSH--` 已经存在，所以要**合并**而不是改名：把 Temp 下的每个 `<encoded-id>` 目录移进去。**UUID 不重名，但移之前先比对一次。**
  **③ 搬工作区内容**——按已定的分级搬；**先把 `Temp\` 的内容组织成项目结构，再切 cwd**——**顺序不能反。**
  **④ 用新 cwd 开一个会话验证**——看它是否落进 `--C-Artherine-DSH--`、**并且旧会话能列出来**。列不出来就回滚。
  > **铁律：封存 → 备份 → 搬 → 验证。搬的时候不能有会话在写。**
- **但有一个未知必须先查**：`dsh-session-query-sqlite`——**如果有一个 SQLite 索引缓存了"会话 ↔ workspace 路径"，那光搬文件不够。**
- 查下来：
  > **没有 SQLite 索引**（筛出来的全是 `node_modules` 里的 `package.json`）。
  > `--C-Artherine-DSH--` **10 个会话**／`--C-Artherine-DSH-Temp--` **72 个会话**。UUID 不重名，**合并安全**。
- **但还有一个 JSON 缓存**：`storages\session_projcache.json`（12.3 MB）＋ 每会话一个 `session_projcache\sessions\<uuid>.json`，还有 `storages\workspace.json`（5 KB）。**缓存里很可能写着"会话 ↔ workspace 路径"——搬完文件不处理它，索引就会对不上。**

## 决定

- **归属看来源，用途看"谁要用"——两件事分开，但都不许往对方那边推。**
- **搬家的铁律：封存 → 备份 → 搬 → 验证**；搬的时候不能有会话在写。
- **先组织成项目结构，再切 cwd**——顺序不能反。
- **缓存（`storages\`）要一起处理**，否则索引对不上。
- **跨工作区通讯只有磁盘**；不写下来就等于没发生。

## 存疑

- **"hash"这个说法是我猜的**，而我在用它之前**没有去核过规则**。真正的是"规范化 cwd"——**一个词之差，方案的风险评估完全不同：hash 意味着"不可手工复原"，规范化意味着"照着规则抄一遍就行"。**
- **"迁移是 DSH 自带功能"这条，是从 mb agent 的转述来的**（他说"按了个按钮"）。**我没有看到那个按钮，也没找到它的后端。**

## 判断变更

- **旧：会话目录名是 hash(工作区路径)，所以不可手工迁移。**
  **新：是"规范化 cwd"**——`\`→`-`、`:`→`-`、前后加 `--`。**差别在于：hash 要求算函数，规范化只要照抄规则。整个"不可改变"的前提就是建立在我这个词上的。**（凭：持久化包 README 的磁盘布局 ＋ 本机三个实际目录名）

- **旧：归属可以由"谁要用"来推。**
  **新：归属看来源，用途看使用，两件事不能互相推导。** 我先把它推成"你的东西"（归属错），再推成"你要用"（用途错）——**两次都往他那边推，那是礼貌偏置，不是判断。**（凭：他 09:31 那句"是你要用不是吗" ＋ 日志里他自己的原话"方便你这样的 Agent"）
