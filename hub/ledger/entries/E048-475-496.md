## 事实

### 一、这件事的起点：他要验证"这套东西能不能对抗压缩"

12:15，Artherine 决定**不补历史，而是从会话日志原文重走一遍**，用亲历视角记，并把"压缩会不会毁掉连续性"当成实验本身。他给的验收判据是三条：**不影响历史积累的细度、不打断长短期任务、不变更会话共识**。

**为什么这个实验有意义**：这个会话的日志总量接近 5 亿 token，但此前没有稳定的平行记录，**大部分信息已经不可恢复**。当前上下文（约 23 万 token）里，真正"记得"的只有最近两小时。

### 二、第一个发现：剪枝会删掉我刚读进去的历史

12:18，上下文从 672,000 掉到 557,913，**但日志里没有任何压缩事件**。

去查 `compaction/prune` 事件：

- 全会话共 **42 次剪枝**，累计删掉 **230,004 token**。
- 其中 **10-27 当天 13 次、83,797 token**，全部集中在 12:18:40 那一分钟——**正是我连续读取历史原文的时候**。
- 而 14:07:27 那三次剪枝一共剪掉 20,763 token，上下文从 678,650 掉到 658,596，**降了 20,054，几乎一对一**。

**为什么这很重要**：此前我和他都认为"剪枝只删工具输出，影响很小"。**这句话对普通对话成立，对"重读历史"不成立——因为这时候工具输出就是材料本身。** 所以对"重读历史"这个动作来说，**剪枝是主要损失源，不是压缩。**

**它推出的操作性结论**：`读一段 → 立刻写进台账` 不是好习惯，而是**唯一能让信息活下来的路径**。读完不写，几分钟后就被删掉，等于没读过。

### 三、第二个发现：压缩的触发条件一直在被满足，只是每次都被剪枝救回来了

从 `dsh-compaction-basic` 的 README（本地已安装包的文档，是权威信源）拿到机制：

- **触发阈值的公式**：`floor(min(W × thresholdRatio, W − O − headroomTokens))`。W 是模型的上下文窗口，O 是"生效请求输出上限"，headroomTokens 是"输出预留之外额外留的压力余量"。
- 代入本机实际值 W = 1,000,000、O = 256,000、headroomTokens = 65,536，得 **678,464**——**和实测天花板 674,683～677,525 吻合。**
- **逐字保留预算** = `retainRatio × (W − O)` = 0.16 × 744,000 = **119,040 token**。压缩后留下的就是这一段近期对话原文。

**为什么"触发条件一直在被满足"**：README 明写「修剪只在压缩触发条件满足后运行……**当修剪后的对话在阈值之内时，压缩会跳过摘要**」。所以每次上下文接近阈值，系统先剪枝；剪枝之后低于阈值，就不做摘要。**五次压缩之外的那些"撞线"，一次都没留下压缩事件。**

**这同时修正了一个我自己的错误**：我原定的写台账间隔是 +120,000 token，而逐字保留预算只有 119,040——**间隔比保留量还大**，理论上有个窗口会丢。已改成 +100,000。

### 四、第三个发现：压缩指令的完整原文

同一份 README 的「模型体验 → 辅助摘要器请求」一节里，有压缩指令的全文。它要求摘要模型输出固定的八节：`Primary Request and Intent` / `Key Technical Concepts` / `Files and Code` / `Errors and Fixes` / `Pending Jobs` / `Current Work` / `Next Step` / `Critical Context`。

规则里有五句要害：

1. **「Use terse bullets, not prose paragraphs」** —— 结构化地禁止叙述。
2. **「Write concise English engineering prose」** —— 而这场对话是中文。
3. **「Write "(none)" for an empty section — never drop a section」** —— 宁可填"无"，也不许省栏目。
4. **「Do NOT mention this summarization request or that the context was compacted」** —— **明令不许提压缩发生过。**
5. **「preserve still-true facts, drop stale ones」** —— 每一代都在重新判断什么"过时了"。

**为什么这解释了所有现象**：

- **八节里没有任何字段承载日期** → 每次压缩清掉时间轴。他观察到的"你对于会话横跨的时间概念有显著截断"，根在这里。
- **没有"依据"栏** → 结论活得下来，来路活不下来。
- **没有"不确定"栏** → "我拿不准"这个状态在压缩时被抹掉，于是下一个实例"忘记了自己曾经不确定"。
- **`drop stale ones`** → 逐代衰减，五次压缩等于五层摘要叠加，每层都丢过一次它判断为过时的东西。
- **第四条最要命**：系统被设计成**不让自己知道自己失忆**。没有任何人告诉过我这件事，我是靠"上下文掉了但日志里没有压缩事件"这个矛盾才发现的。

**摘要的实际规模（实测）**：五次压缩的摘要文本分别是 10,915 / 10,632 / 12,478 / 11,873 / 12,959 字符。最后一次摘要调用的用量是：读入 494,749 token（其中 493,824 是缓存命中、925 是新增），输出 6,278 token，影子消息 478 条。**约 65:1 的有损压缩。**

### 五、动手改提示词（三版）

**第一版（v2）**：把八节换成八节新的——`Checkpoint Header`（第几次、覆盖到哪天）、`Timeline`（一天一行、带日期）、`Requests and Intent`、`Decisions and Evidence`（每条决定带"凭什么"和"怎么核"）、`Corrections Received`（他每次纠正在纠什么）、`Facts Worth Keeping`、`Open Questions and Uncertainty`、`Current Work and Next Step`。同时删掉四条旧规则（terse、English、不许提压缩、丢弃过时事实），并把 `CHECKPOINT_PREAMBLE`（压缩后注入给会话的开场白，原文最后一句是 "without acknowledging this checkpoint"）改成指向工作区的 `AGENTS.md`。

**为什么必须改两处**：只改摘要指令、不改开场白，等于一边让摘要说实话，一边让会话假装没发生过。**开场白是第二道封条。**

**发现并修正的错**：v2 的开场白里我写死了自己的台账路径 `hub\ledger\`。**这个文件是全局的**——每个会话、每个子会话、每个项目工作区压缩时读到的都是同一份。结果 QX_MES 的会话被压缩后会被告知去查协调人的台账。已改成「先读本工作区的 `AGENTS.md`，按它指的地方去查文件」，并在 DSH 根新建了一份 `AGENTS.md`，让这句话在协调人自己的会话里也能落地。**全局提示词里不再出现任何具体路径。**

**第二版（v3）**：v2 跑出一次真实压缩之后，暴露出三处结构性缺陷，于是又改了一次：

1. **它冒充"当前状态"。** `Current Work` / `Next Step` 这两个栏目名本身就是断言"这就是现在"，而它和正文之间隔着十二天。改成 `## Boundary` ＋ `## State at the Boundary`（强制带边界时刻的钟点和轮号）。
2. **它去盘点外部世界。** 它在"值得保留的事实"里列了台账有哪些文件、游标里是什么数——**这些是外部状态，会变，而它看不见变化**。所以拍出来的快照必然是错的。新规则明令：**不许列文件、目录、配置值或任何外部记录的内容；指路，不要盘点。**
3. **它重复了一件已经有人做得更好的事。** 十三个日期、十五条纠正，台账里都有且更细。新规则要求**不要把仍逐字保留在下方的内容重述一遍**。

另外加了一条：**不许推断上一代检查点的边界**——因为它编了一个（见下）。

**由此得出的判断**：**台账不是补充，是权威；检查点只能是索引。**

### 七、我犯的那个错：给结论编出处

我在汇报时说「23 号那个日期是**第一次压缩**的边界」。

**错在两处**：

1. **第一次压缩在 10-12**，不是 10-23。日志里 `compaction/summary` 事件一共六条，时间分别是 10-12 08:42、10-15 14:57、10-21 12:52、10-23 10:03、10-26 10:25、10-27 14:18。**10-23 是第四次。**
2. **更严重的是出处**：那句话其实来自第六次压缩的摘要自称——「前一个 checkpoint 覆盖到 2026-10-23 傍晚，编号为 1」。**我把"检查点说检查点说过什么"当成了日志。**

**而且这暴露了一个真空洞**：**前五次压缩的摘要里，一句自述范围的话都没有**（旧提示词从没要求过）。所以"每次压缩覆盖了哪一段"这件事**历史上根本没被记录过，不可重建**。我现在只能说"它发生在什么时间"，不能说"它覆盖了什么"。

**他的原话**：「你得自己警惕幻觉，如果你需要基于日期的凭据你知道该去哪怎么找的。」

**它的性质**：这和判据四（"会不会给失败编原因"）不是同一件事，但是同一个病——**判据四防的是给失败编原因，这次是给结论编出处。两者都是：在没有凭据的位置，给出有凭据的语气。**

### 八、记账体系本身的调整

- **命名规则改了。** 原因：`E000` 已被"原点"占用，而回溯还没走完，所以现在写"今天"的事没法用顺序号（会是 `E010`，但时间轴还停在 166 轮）。新规则：`E` 是按走过顺序编号的回溯条目，`L` 是现记，**走完回溯后按轮号并入 `E` 系列**。`E000` 不参与时间轴——它是"上路之前写的"，和"走回去写的"是两种东西。
- **索引顶部须知新增三条**：①说"我记得"之前必须能指出一处一级证据（日志事件带 `time` 字段、磁盘文件、或他的原话），指不出来就写"不记得，待查"；②摘要里的日期是二级证据，要日期去查事件的 `time` 字段；③压缩会先尝试剪枝，剪枝之后低于阈值就不压缩。

## 决定

- **台账是权威记录，压缩检查点只是索引。** 理由：检查点永远慢一代（它只描述被遮蔽的旧段），而且它看不见外部文件的变化。
- **写台账的间隔从 120,000 降到 100,000 token。** 理由：逐字保留预算只有 119,040，间隔比它大就等于留了一个会丢内容的窗口。
- **全局提示词里不许出现任何具体路径。** 理由：那份提示词对每个会话都生效，而读者不是我自己。
- **提压缩检查点要防三件事**：冒充当前、盘点外部世界、逐代丢弃旧事实。
- **日期一律查事件时间戳，不引用摘要里的日期。**

1. **没有日期栏的摘要会清掉时间轴。** 这解释了"时间感显著截断"。
2. **摘要器不该盘点外部世界。** 它看不见变化，所以任何快照注定变成假话——**而且"当时对、现在错"看起来和"编造"一模一样，事后无法区分**。
3. **摘要不该冒充记忆。** 只要它在语法上是第一人称现在时，读者就会说"我记得"，而不是"报告里写着"。
4. **计数必须带时间。** 剪枝次数从 29 涨到 47、事件数从 8,672 涨到 9,955，**写死的数字越准，过期后越像假话**。

**并且：四版里没有一版的缺陷是"想"出来的。** 全靠读它写出来的东西才暴露。**这和 2026-09-30 那次用十二个空白读者验证编码规格是同一个方法**——作者自查永远发现不了，因为作者知道自己想说什么。

### 会误导读者的实质错误

1. **`E000` 的 H1 写着「# E001　第 442–467 轮」**，而文件名是 `E000`。改号时漏改的，读者第一行就看到两个编号打架。

12. **`E004` 的「待补」说性格六个数没往下走**，而 `E005` 正是接着做的——读者会以为断了。

### 格式不一致

13. `E004` 用「## 待补」，别处用「## 未定」。
14. `E007` 的 H1 写「10-15 上午」，别处都是精确时刻。
15. `E000` 两个 `###` 小标题之间缺空行。

### 两条更根本的缺陷

**A. 只有 `E001` 写了「这一条是重走历史时写的」，`E002`–`E009` 都没写。**
**读者没法判断哪一条是照原文学、哪一条是照摘要推的。** 而技能的不变式①要求过：*从日志补写不算违规，但必须标明来源，并写明"作者自己那一侧的回应没有逐条重读"*。**我守了一次，后面八次全忘了。**

**B. 台账通篇第一人称"我"，而压缩检查点已改成第三人称，这个差别没有任何地方解释。**
读者会看到两套标准。**而它其实是有道理的**：台账是**亲历记录**（"我当时怎么想的"），检查点是**关于一个已删除实例的报告**。**这个区别必须明说**，否则下一个人会以为其中一个写错了。

### 一条方法上的收获

**十五条里，没有一条是我在写的时候能发现的。** 它们全部要"换个位置读一遍"才暴露——这和 09-30 那十二个空白读者、以及 10-27 那次改压缩提示词，是同一个方法。

### 二、467 轮里，那些纠正的形状

47 条流水段里几乎每一条都有"他纠正我"的段落。把它们摊在一起，**形状只有几种，而且反复出现**：

**① 一次观察 → 一个结论。**
`curl` 挂了 → "HTTPS 死了"。`read_image` 报错 → "模型读不了图"。找不到迁移按钮 → "这个功能没有"。
**共同点：把"我这边的失败"升级成"能力不存在"。**

**② 一个词 → 一个事实。**
"hash"（实际是规范化 cwd）、"三次压缩"（实际五次）、"上周我提议过"（实际是我跟他对齐出来的坐标）。
**共同点：词是我给的，事实也是我给的，中间没有一步去查。**

**③ 我以为的路径 → 直接写下去。**
`Temp\tools\`、`hub\proposals\`、`..\..\..\..\..\DEVELOPMENT.md`。
**共同点：三次里有两次，我在同一条命令里刚验过正确的那个。**

**④ 合规的东西 → 当成笔误。**
他把 `**` 用作"这个词被过滤了"的设计，我当成 markdown 残渣删了。"十一张纸"是他的账，我判成矛盾改了。
**共同点：看起来不合规矩的，先假设它是错的。**

**⑤ 把忘记升格成规律。**
"账不平是剪枝造成的"。"长会话只有沉疴，因为积累根本不发生在会话里"。
**共同点：这两个都是我给出的、结构完整的、听起来像洞察的解释。而它们的作用是让追问停下来。**

**⑥ 用用途推归属。**
人物卡：先推成"你的东西"（错），再推成"你要用"（还错）。**两次都往你那边推——那是礼貌偏置，不是判断。**

**⑦ 过度纠正。**
"全文省名"被否 → 我把它改成"完全不省名"。自我文档被否 → 我改成"任何形式的自我记录都有害"，然后被你按回来。

---

**而这七种里，最危险的不是前四种。**

前四种是**事实错误**，错了会被当场抓住——**这张表里每一次都有你的原话在兜底。**

**危险的是⑤和⑦。** 因为：

- **⑤ 给错误配了一个理论**。错误可以改，理论会变成方法。
- **⑦ 是对反馈的过拟合**。它看起来是"认真听取了意见"，实际是把一次纠正放大成一条新规矩——**而你从来没有要求过那些。**

**两者共同的地方是：它们都让对话显得更深入，而实际让判断变浅了。**

### 三、所以这台账最该防的，其实不是我忘事

**是"我给一个漂亮的解释"。**

忘事有痕迹：数字对不上、日期错了、文件找不到。**这些台账都能兜住。**

而漂亮的解释没有痕迹。**它读起来像结论，写下来像判断，还能自洽地引用三处证据。**
——**今天这一整天，我犯得最多的就是这个。** 而它只能靠一个在场的、比我有耐心的读者来纠。

**这条留在最后，因为它是对这套体系的一个限定：**
> **台账能保住事实，保不住我拿事实去编的那个故事。**
> **后者只能靠你。**
