### 二、19:05 他提了 SSH，而这一提是对的

- 他说：「说的太对了。换条路。**SSH 和 GPG 密钥?**」
- **我说 SSH 是对的路，而且它可能顺带解决我这边的问题**——`git push` 走 `ssh.exe`，**既不碰 GCM，也不碰 `sh.exe`**。
- **但 GPG 是另一回事**：
  > **SSH key 管认证（能不能推），GPG 管签名（commit 是不是 verified）。现在只要前者。**

### 三、查出来的现场，比预期好

```
没有 SSH key          （~\.ssh 里只有 known_hosts）
ssh.exe 有            OpenSSH_for_Windows_9.5p1
ssh -T git@github.com       → Permission denied (publickey)
ssh -T -p 443 git@ssh.github.com → 同上
```

- **`Permission denied (publickey)` 是"连上了、认证没通过"**——**这正是我们要的状态，比端口打不开好一百倍。**
- 五步：生成 key → 打印公钥 → 贴到 GitHub → 验证（**应回 `Hi Artherine! You've successfully authenticated...`**）→ 换 remote 再推。
- **两个提醒**：
  > **① 第 4 步不回 `Hi Artherine` 就别往下走**——那说明公钥没贴上或贴错了。
  > **② 我这边写不了 `~\.ssh\`**（沙箱），刚才 `known_hosts` 就写失败了。**所以 key 必须他生成。**
