### 五、回到同步：用"变质速度"一量，方案自己出来了

| 东西 | 多久变一次 | 怎么同步 |
|---|---|---|
| **`.mnemon\`**（记忆） | **慢**（一天几次） | **它本来就在 git 里** → `git push/pull` 就是同步 |
| **`Temp\`**（工作区） | **中**（每轮改） | 同一仓库；换设备走 git |
| **会话日志** | **快**（每回合追加） | **不同步**——切换前 `/export` 成 ZIP，丢进仓库 |

- **最小方案就是两个仓库，不嵌套、不搞子模块**——各自 `pull`/`push`，谁也别管谁。
- **两个现成件的分工，别搞混**：
  > **git 管"跨设备"**（有历史、能处理冲突）；
  > **`dsh-workspace-changes` 管"跨回合"**（这一轮改了哪些文件）。
  > **它记的是台账，不是备份。** 别拿它当同步。
- **还有一个坑当天已经踩过**：换设备后环境不一样（`npm.cmd`、`--cache`、代理出口、Java 路径全变）。所以 `pull` 之后该跟一条 **`envcheck`**：**和记录不符就报警，别硬跑。**
  > 这就是他说的"把环境特征写进上下文"，只不过写成**可执行的检查**，不是一段说明。

### 六、09:16 找到那个"综合云存储"仓库

- 他说：「其实最方便的就是和 mnemon 共用仓库……**那个仓库本来就是我用来放些需要云存储的文档的，算是个综合云存储位置**。如果你能直接从插件里拿到凭证的话，连上去看看。」
- 查出来的事实链：
  - `.mnemon` **本身不是 git 仓库**（只有 `data / documents / runtime / state`）；
  - 但 `credential.helper = manager` 来自 **system 级 gitconfig** → **凭证由 Windows 凭据管理器提供，git 能用它，但我读不到密码（这是好事）**；
  - **找到了 `~\.mnemon\state\sync-git.json`**：`repoUrl = https://github.com/Artherine/vps.git` → **mnemon 自带 git 同步**；
  - **`ls-remote` 直连成功**（`github.com` 现在通），两个分支：`main` 与 **`mnemon-sync`**；
  - **`mnemon-sync` 分支里只有 `mnemon/` 一个目录**，提交信息 `Mnemon sync 2026-10-16T01:01:07Z`。
  > **所以 mnemon 的模式是：用专用分支 `mnemon-sync` 存它的 `mnemon/` 目录，不碰 `main`。** 这正好是"共用仓库"——**而且它已经把"怎么放"做出来了：分支隔离。**
- **而这里我犯了一个小错**：上一轮我打印 `sync-git.json` 时用的是 `$_.Filename`（只有文件名），**没打路径**，于是下一轮 `Test-Path` 说它不存在，**我自己吓了自己一跳**。真实路径在 `state\` 子目录下。
- **schema（照抄它的命名）**：
  ```
  branch            = mnemon-sync
  subdir            = mnemon/
  authorName        = dsh-mnemon sync
  authorEmail       = mnemon@localhost
  autoBackupMinutes = 0
  repoUrl           = https://github.com/Artherine/vps.git
  ```
  > **六个字段，没有一个 token。** 认证完全交给系统凭据管理器——**配置里不含密码，所以这份 json 可以安全地留着。**
- **建议照抄它的形状**：同一个仓库 `Artherine/vps`，新开一个分支 `workspace-sync` 放 `workspace/`。
  > **为什么是分支而不是新仓库**：凭据、远端、习惯全都复用，而且 **mnemon 已经证明这个形状能用**。
- **三样必须挡在门外**：`node_modules/`（mc-bot 里 91 个包）／`scratch/`（含一个 25 MB 的 `live.jsonl`）／`npm-cache/`（几百 MB）。**不 .gitignore 这三样，第一次 push 就是一场事故。**
- **还有一条从它身上学到的，比 schema 重要**：
  > **配置放在 `state\`（不同步），内容放在 `mnemon\`（同步）。**
  > **同步目录里放配置，两台机器会互相覆盖。**
