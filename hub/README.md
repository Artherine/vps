# hub —— 顶层框架

> 这个位置放的是**跨工作区的东西**：谁在做什么、为什么这么定、怎么找东西。
> **它不属于任何项目**，也不该被某个项目的具体问题污染。

## 三个位置，各管一件事

| 你想知道 | 去哪 |
|---|---|
| **现在在做什么** | `changes\` —— 活跃，**完成即删**（短命） |
| **发生过什么** | `board\` —— **只追加**，永不改 |
| **为什么这么定** | `decisions\` —— 只增，只被新决策取代 |
| **某个东西怎么用 / 这个坑怎么绕** | `kb\` —— 有主，带复核日期 |
| **有哪些工作区、谁负责、卡没卡** | `WORKSPACES.md` |
| **谁能写哪儿、什么算完成** | `AGREEMENT.md` |
| **等我拍板的事** | `PENDING.md` |
| **别人提的改动方案** | `proposals\` |
| **压缩之后要查事实与依据** | `ledger\` —— **先读它的 `index.md`**（常读层：须知 ＋ 话题表） |
| **废弃但仍有价值的旧文档** | `archive\` —— **每份头上都有墓碑，说清它什么时候失效** |

**`ledger\` 是这套东西里唯一"专为压缩而建"的部分，和 `kb\` 不是一回事：**

- `kb\` 放**结论**（某个坑怎么绕）；
- `ledger\` 放**来路**（哪一轮定的、当时凭什么、变过几次）。

**压缩带走的正是来路，不是结论**——两个都要，缺一个就退回"一堆没有依据的结论"。

**`changes\` 和 `board\` 是两个目录，不是同一个。** "合并即删"和"只追加"是两种节拍；混在一起会互相打架。

## 路径契约（重要）

**所有跨目录引用一律用相对路径。** 这套东西会跟着人换设备，而**别处的 DSH 路径未必和这里一样**。

| 从哪看 | `hub\` 的相对路径 |
|---|---|
| 工作区根 | `hub\` |
| 项目目录（`projects\<名字>\`） | `..\..\hub\` |
| 工具（`tools\`） | 从项目看是 `..\..\tools\` |

**所以目录深度是契约**：

- **`hub\` 必须在工作区根下**；
- **每个项目必须在 `projects\<名字>\`**（固定两层）；
- **`tools\` 必须在工作区根下**。

深度一变，别人的相对路径就全断。

## 什么同步、什么不同步

**“留本地”和“上云”是两件事。** 云仓库有预算（体积、频率），**不是所有本地有用的东西都该上去**。

| 类别 | 留本地 | 云同步 | 例子 |
|---|---|---|---|
| **本体** | ✓ | ✓ | `hub\`、会话日志、`~\.mnemon\` |
| **作品** | ✓ | ✓ | `projects\story`、`projects\roscoe-halfside` |
| **参考资料** | ✓ | **✗** | `projects\dnd`（规则书，59 MB，别处都有备份） |
| **可重建** | 看需要 | **✗** | 一次性产物、`node_modules`、导出的日志副本 |

**判据**：**同步的是“丢了要花大代价才回来”的；不同步的是“丢了重拿很便宜”的。**

## 这里不放什么

- **不放项目文档** → `projects\<名字>\`
- **不放工具** → `..\tools\`
- **不放会话记录** → 那是 `.dsh\sessions\` 的事，不是文档
- **不放"给某个工作区的通知"** → 写进那个工作区的 `AGENTS.md`
