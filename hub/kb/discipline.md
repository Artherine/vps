# 工作纪律

> 这几条不是原则，是**我反复犯的错**。每条后面跟着真实的代价。

## 一、前后对比，必须同源同刻

**同一件事的两个数字，如果取自不同时刻，差的那个不是错误，是时间。**

两次代价：

- **`mb` 会话文件"变大 129 KB"**——迁移前的清单 vs 迁移后的文件，中间用户打开过它；
- **`QX_MES` 会话"18 变成 19"**——迁移前的台账 vs 迁移后的台账，中间有会话被归组。

**判据：动手对比之前，先问"这两个数是什么时候取的"。**

## 二、写进文档的路径，写完必须验

**路径不会报错，它只是指向空。** 所以它是文本里最容易错的东西。

三次：

- `Temp\tools\` 还写进热层时，工具已经搬走了；
- `AGENTS.md` 让项目 agent「写 `..\..\hub\proposals\`」——**它们的写沙箱根本到不了那里**；
- 任命书里写 `..\..\..\..\..\DEVELOPMENT.md`，而文件就在同一目录——**而且同一条命令里我刚打印过"✓ 在同目录"**。

**做法：写完立刻用 `Resolve-Path` 一条条列出来，别目测。**

## 三、给别人的指引，必须先验它做得到

**第二、三次是同一类：我写的是"我认为对的做法"，不是"他做得到的做法"。**

**判据：这条指引，接收方有没有那个权限、工具、路径？**

- **权限**：项目 agent 写不了 `hub\` → 提案通道只能是「我来取」，不能是「你来递」；
- **能力**：我没有耳朵 → 名字顺不顺口要靠音标推，不能靠"我念一遍"。

**代价：一条用不了的指引，比没有指引更糟**——它让人要么绕路，要么放弃，**而它看起来还是对的。**
## 四、上一条命令失败了，别接着跑下一条

**`Push-Location` 到短名路径失败后我没检查，继续跑了 `git init` 和 `Set-Content`**——两条都落在错误的目录，在工作区根留下一个 `.git` 和一个 `README.md`。

**更隐蔽的一次**：`git push --dry-run | Select-Object -First 12`——**管道把退出码一起吞了**，`$LASTEXITCODE` 读到 0，真实值是 128。

**做法**：

- 任何 `Set-Location` / `Push-Location` / `cd` 之后，**立刻打一次 `pwd` 对一眼**；
- **别用 `| Select-Object` 包住会返回退出码的命令**——它让你读到的是管道最后一段的状态，不是那条命令的。
## 五、日志里打的必须是查到的，不是打算的

**`hub-sync.ps1 -Action init` 打印了 `远端: https://…`**——那是我 echo 自己的变量，**不是 `git remote -v` 的输出**。
结果 `origin` 根本没加上，人照着那行"成功日志"去 push，拿到 `fatal: 'origin' does not appear to be a git repository`。

**做法**：

- **写完配置立刻读回来打一行**——`git remote -v`、`Get-Content`、`Test-Path`，**读到的才写进日志**；
- **别把「我设了这个变量」当成「这件事成了」**。
## 六、在「不知道为什么失败」的环节上，不要反复试

**推 `hub-sync` 失败了三轮**：网络（`Connection reset` / `port 443 timeout`）→ 凭据（`Invalid username or token`）→ GCM 没弹窗。

**第三轮之后我还在猜 GCM 为什么不弹**——而答案不是"猜对第三个"，是**换成 SSH key，一次就通**。

**判据：同一件事试到第三遍还失败，就换一条不依赖那个未知环节的路。**

- 不确定 GCM 为什么不弹 → **用 SSH，绕过 GCM**；
- 不确定 `sh.exe` 为什么崩 → **用 HTTPS，绕过它**。

**猜得越多，沉没成本越大，越舍不得换路。**
## 七、给人在 agent 之外运行的脚本，输出必须落盘

**2026-10-27：`link-sessions.ps1` 被人在 DSH 关闭后运行，输出一闪就过了，几乎看不见状态。**

**它不是"不好看"，是"没法用"**——一个需要人判断"检查过没过"的脚本，把结论打在会随窗口关闭而消失的控制台上，等于没打。

**做法**：

- 脚本自己写一份日志到工作区（如 `tools\logs\<脚本>-<时间>.log`），并在退出前打印**路径**；
- **关键结论要重复在最后三行**，别指望人往上翻；
- 需要人确认的脚本，**默认 `-DryRun`**，真跑要显式去掉。

## 八、照抄自己以前写的东西时，抄了骨架会漏掉安全带

**`migrate-project.ps1` 有 `-DryRun`（阶段 A 只生成 .tmp 并校验，一个不动）；`link-sessions.ps1` 第一版没有——我照那个形状写，把最关键的一半丢了。**

**而它比别的错更难自查**：因为它看起来"和上次一样"。

**做法**：复用旧脚本时，**先列它的控制项清单**（dry-run / 备份 / 回滚 / 校验 / 日志），逐项勾，别凭印象。
## 九、`| Out-String` 会按控制台宽度折行，把 JSON 从中间截断

**2026-10-28：`session-sync.ps1` 里把 `& node ... usage $path | ConvertFrom-Json` 改成了 `($raw | Out-String) | ConvertFrom-Json`——一路"改进"，结果报 `Unterminated string`。**

**原因**：`Out-String` 是**格式化输出**，它会按当前控制台宽度插换行。JSON 是单行长文本，一折就断在字符串中间。

**做法**：

- 解析命令输出用 **`($raw -join [Environment]::NewLine)`**，不要用 `Out-String`；
- **或者干脆不接**——`ConvertFrom-Json` 能吃数组，直接 `| ConvertFrom-Json` 就行（我原来那版就是这么写的，是我把它改坏的）；
- 判据：**凡是"要再被解析"的文本，一律不许过 `Out-String`／`Format-Table`。**

**这一条的性质和第七条一样**：我在沙箱里跑，输出不折行；人跑的时候折了。**又一次按"我这边的环境"写，而不是按"它会在哪儿运行"写。**
