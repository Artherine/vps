# changes —— 活跃任务

> **一文件一事；完成即删。**

## 为什么它不在 `board\` 里

| | 回答什么 | 节拍 |
|---|---|---|
| **`changes\`（这里）** | 现在手头有什么 | **短命，会被删** |
| **`board\`** | 发生过什么 | **只追加，永不改** |

**混在一个目录里，两种节拍会打架**：一个要删，一个要留。

## 一个任务一个文件

文件名：`<来源>-<动词>-<对象>.md`，例：`叙-迁-mb到projects.md`

开头四行就够：

```yaml
owner: 谁在做
from: 从哪来的（PENDING 的编号 / 某条提案 / 某个工作区）
done-when: 什么算完（可核对，不是"他说完了"）
```

下面随便写，**但不要复制正文**——引用的东西给指针。

## 删的条件

**两件事同时成立才删**：

1. 交付物在；
2. 结论落了（`kb\` 或 `decisions\`）。

**删不是销毁**——删之前把"做了什么"写进 `board\` 一行。
