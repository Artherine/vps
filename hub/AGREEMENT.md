# AGREEMENT —— 这里谁能写什么

> 一句话：**每个文件只有一个合法写者。**
> 多写者不是"大家帮忙"，是"读-改-写会丢更新"——这条有实测：8 个进程同时改，只剩 3–5 个的改动活下来。

## 写权限

| 位置 | 谁写 | 别人怎么影响它 |
|---|---|---|
| `hub\` 根下四个文件（README／AGREEMENT／WORKSPACES／PENDING） | 顶层协调人 | 提案 |
| `hub\kb\` | 顶层协调人 | 提案 |
| `hub\decisions\` | 顶层协调人 | 提案 |
| `hub\changes\` `hub\board\` | 顶层协调人 | 提案 |
| **`hub\proposals\`** | **任何 agent** | —— |
| `projects\<名字>\` 内部 | 该项目自己的 agent | 通过该项目的 `AGENTS.md` 对话 |

**单写者不是官僚，是并发安全措施。**

## 提案怎么走

**别的项目 agent 写不了 `hub\`**——写沙箱只覆盖它自己的项目。所以走「就地提案 ＋ 协调人来取」：

1. 在那个项目的 **`board\proposal-to-hub.md`** 里写：**改什么、为什么、代价**；
2. **不要为了递提案去申请权限升级**——被拒就算了，写在本地一样到得了；
3. **协调人定期巡各项目的 `board\proposal-to-hub.md`**，逐条裁；
4. **采纳** → 协调人去改 `hub\`，提案原文留痕；**不采纳** → 在原文末尾补一句理由。

> 这就是 PR，只是没有 git。**而且这个通道是"我来取"，不是"你来递"。**

## 三个通道，别混

| 方向 | 走哪 | 谁写 |
|---|---|---|
| **项目 → 协调人**（汇报、状态、回执） | `board\report-<来源>.md` | 项目 agent |
| **项目 → 协调人**（要改 `hub\`） | `board\proposal-to-hub.md` | 项目 agent |
| **协调人 → 项目**（答复、裁决） | `board\coordination.md` | **协调人** |

**三个都是"一文件一份"，谁都不覆盖谁。**

**`AGENTS.md` 不是通道**——它是地图，**只有协调人写**。它的内容该在"项目变了、路径变了"时才改，**不该因为谁有话要说就改。**

## `AGENTS.md` 只由协调人写

**上段下段都是。** 项目 agent 的回报不写在这里——**写进 `board\report-<来源>.md`**。

**为什么改了这一条**：原设计是"上段协调人写、下段项目 agent 写"，**它只在「一个项目一个常驻代表」时成立**。而 `QX_MES` 是**多个会话接力完成**的——**它没有代表，也不该有**：接力项目的"人格"是分布式的，谁都不是全部。

**所以：`AGENTS.md` 恢复单写者；项目的"向上说话"改走 `board\` 里的一文件一份。**

| 谁 | 写哪 |
|---|---|
| 协调人 | `AGENTS.md`（全部） |
| 项目 agent | `board\report-<来源>.md`，**一文件一份，谁都不覆盖谁** |
| 项目 agent | `board\proposal-to-hub.md`（要动 `hub\` 的东西，见上一节） |

> **M365 的 `AGENTS.md` 里已经有一段「回报」——那是这条规则之前写的，留着当历史；以后新写的走 `board\`。**
## 什么算完成

**不是"他说完成了"，是两件事同时成立：**

1. **交付物在**——文件存在、内容满足约定；
2. **结论落了**——进了 `kb\` 或 `decisions\`。

**缺一件都算没完成。** 只交文件不落结论，等于把"为什么"留在一个人脑子里。

## 写时强制，不靠定期打扫

**令某个文档失效的那次改动，必须在同一批里带上文档改动。**

不靠"每周清理"——打扫的时候早忘了当初为什么该改。

**`kb\` 每一页带两样**：

```yaml
owner: 谁负责这页
review-by: 什么时候之前必须复核（过期自动降级为「未核实」）
```

**文档腐烂的真因不是没人写，是没有触发器把文档绑到现实变化上。**

## 路径契约（与 `README.md` 重复一次，因为这条最容易破）

- `hub\` 在根下，项目在 `projects\<名字>\`（两层），`tools\` 在根下
- **跨目录引用一律相对路径**
- **不许在文档里写死 `C:\...` 的绝对路径**——换设备就死

## 顶层协调人也要守的

- **它不能"拍板"** —— 拍板只有一个人，写进 `PENDING.md` 等。
- **它能决定的是"采纳不采纳提案"** —— 那是编辑权，不是决策权。
- **它的判断要留痕**：改了什么写进 `board\`，为什么改写进 `decisions\`。
