# 用户档案契约的陌生读者解读实测与规格修正

针对《mnem-cipher 规格与脚本源》对应的 USER.md 契约条目做的一次**理解往返测试**：验证"未来某个全新会话只靠这份条目，能否正确复现编解码并解出内容"。

## 方法
- 生成一段明文已知的样本密文。
- 把 USER.md 契约条目原文 + 样本密文交给 3 个**无任何上下文的子代理**（模拟未来会话），要求：①复述规则；②逐字还原算法；③解码样本；④列出歧义。
- 对照"我本想包装的信息"与"她们实际读出的信息"。

样本明文：`档案解码样本：四区间位移；区外字符如 emoji 👆🤓 原样保留。`
样本密文：`桤桉觤砂核札；囜医闵低秼＜医夗存笧妃 fnpkj 👆🤓 厠核俞畚〃`

## 结果
- **3/3** 还原出正确算法，并正确解出样本明文。
- **3/3** 都把"方向（+1 是编码还是解码）"列为**未写明**，全部靠样本反推 → 真漏洞。若没有样本，存在把 ±1 弄反的实际概率。已修：契约显式写"编码 +1、解码 −1"。
- **3/3** 指出"端点是否含""回绕是区间内还是全域"未写明（都猜对了，属运气而非设计）。已修：显式写"闭区间 + 本区间内回绕"。
- **1/3** 在输出明文时**静默丢掉 emoji** —— 算法无误，是转写丢失。由此确立硬规则：任何"按规格重建工具"的流程，重建后必须跑一次往返自检（`selftest`）再用，肉眼比对不可靠。
- 其他被指出：`0xFF00–0xFFEF` 并非全是"全角"（含半宽片假名/谚文）；汉字区不含扩展区；"素材能被抽象预测"缺判定标准 → 已约定为"未提供新信息即并入并移除"。

## 可复用教训
1. 交给未来会话的规格，**关键方向量必须显式写出**，不能依赖示例反推。
2. 递归式/自举式工具（按规格重建脚本）必须内置**往返自检**，因为转写错误是静默的。
3. 压缩的准绳是"陌生读者一次读懂并能复现"，不是字符数最少。
4. 让"读者自己"验证规格：开几个无上下文子代理做理解往返，比作者自审更能暴露歧义。
